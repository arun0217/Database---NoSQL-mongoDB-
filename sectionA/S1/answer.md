# MongoDB for a Growing Food Delivery Platform

MongoDB would suit the menu data because menu items do not always have the same fields. One restaurant might list `isVeg`, another might need `preparationTime`, and some items may have an `addOns` list. With a document database, those fields can be added to the relevant item documents as the product evolves. Existing documents do not all need to be reshaped just because a new optional field is introduced. The application still needs to validate the data it accepts, but the database does not require every record to follow one fixed set of columns.

Documents also let related data sit together in a natural structure. For example, a menu item could contain its name, price, vegetarian status, preparation time, and an array of add-ons in one document. The application can fetch the item and its add-ons together, which is convenient when displaying a menu. This is especially useful when those details are usually read and updated as one unit. Data that is shared widely, such as customer records or restaurant-wide details, may still be kept separately and referenced where appropriate.

As order volume grows, MongoDB can distribute data across multiple servers using sharding. This provides a path to horizontal scaling: the system can add servers and spread reads and writes across them instead of relying only on a larger single machine. Sharding needs a suitable shard key and operational planning, so it is not automatic, but it can help when one server no longer handles the workload comfortably.

A trade-off is that flexible, nested documents can lead to duplicated data. If a restaurant's name or address is copied into many order documents, changing it later may require updating multiple records; if one update is missed, the copies can disagree. Relational databases make joins, constraints, and consistency across related tables more direct. MongoDB is a good fit when the data is naturally document-shaped and fields change often, but the team should choose document boundaries carefully and enforce important validation rules in the application or database.
